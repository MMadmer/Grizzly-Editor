## 2. Decisions

- **The default game is `<home>\machine.ltx [game]`, not `grizzly_editor.ltx [game] root`.** The settings file is
  `gz-app`'s and written whole from memory (a domain writer would be overwritten), and headless runs and
  commandlets need the game without the shell. `machine.ltx` also holds the library folder and the association
  switch. Moving it into the settings file is one function (`Machine`) if K wants it.
- **One editor per home, `-home` included.** "A run with its own `-home` ... never hands over" read as: a run on a
  home nobody holds is its own instance. The handover is decided by `editor.lock` of the home alone, so the QA
  proof (same `-home`) works and a fresh `-home` never meets a lock. An update's restart (`-updated`) never hands
  over (its predecessor still holds the lock).
- **The project's own game wins only while it is a game** (checked at the open and at a link): a drive not plugged
  in leaves the project on the default game, so the Link Game card shows only when no valid game is known at all.
- **The converted `game_root` becomes the default** (it goes to `[seen]` and the finder takes it); it is kept as
  the project's own only when it differs from the default.
- **`scene` is written on close only when a scene was open**; a scene outside the project is removed from the file
  at the open. The crash guard of the autoload moved from clearing `last_scene` on disk to `[scene] loading` in the
  machine state, so the git-tracked project file is not rewritten before every load.
- **Tabs live in `<id>.tabs.ltx` beside the state**, not inside `<id>.ltx`: the window writes them whole from its
  own thread; one file, one writer.
- **`project.open` refuses a folder that is no project**; `project.create` opens with `creating`.
- **The project kind is registered in `gz-game`**, not `gz-project`: `gz-asset` depends on `gz-project`.
  `AssetKind::Project` is in the kind table, not in A1's `AssetKind::FILES`.
- **Link Game from the Mod menu opens Preferences > Game** (an action runs a command; the folder picker is the
  page's Change...). The pick list offers every place looked at, valid or not, with its reason.
- **Collect Library Assets** is under File > Project (there is no Project menu); `ui.dialog open id=collect_library`.
- **`bring_in` copies objects only** (groups are expanded into objects when placed); the `library` list is a union
  kept at each save (an object removed from every scene stays listed until Collect).
- **New commands beyond the brief's table**: `project.set_library` (Preferences > Library), `project.associate`
  (the switch and Register Now). `file.copy`/`file.move` declare `overwrite` as `destroys_with`, like `file.import`.
  `game.link find=true` is Find Again; `game.link scope=project` without a path is Use Default Game.
- **QA seam `GRIZZLY_GAME_SEARCH`**: `home` (suites never find the installed game), `installed:<folder>` (stands
  in for the registry). `qa_target` sets `home`; `test_portable` gives the fresh home `installed:` - this machine's
  real installer entry points at a folder that is gone.
