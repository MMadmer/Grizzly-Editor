# E2 - the viewport's own camera, the kit's one pick list, the last comments that cite another program

Closes the critic's findings 2 and 9, the comment list of 6, and the coordinator's three additions (portal
messages, `m_Selected` and the game's field names, the Colour Indices export's write guard).

## A. Shift belongs to the tools (finding 2)

- `crates/gz-ui-viewport/src/camera.rs`: the second camera scheme is gone whole - the Shift claim in `move_start`,
  the `ue` flag (a move is now always the Unreal-style one), `legacy_end` in `move_end`, the `else if` tail of
  `process` (`csPlaneMove`), and `pan` / `scale`, which only it used. `Nav` keeps one `held: Buttons` (what `flying`
  reads). `move_start` claims RMB, MMB and Alt+LMB only; Shift, Ctrl and a plain left press are the tools'.
  The module doc names the scheme that is left. A new unit test (`a_plain_or_shift_left_press_is_the_tools`)
  holds that a Shift+LMB press is not claimed.
- Reachability checked in `pane.rs`: Ctrl marquee (`press_step`), Ctrl-click of a Paint layer, Alt-drag of a gizmo
  handle (taken before the camera), Foliage `erase: b.shift`, Decals `mark_place(.., b.shift)` all see their press now.
  `viewport.gesture` already carried `mods`; no command change was needed.
- Side effect to know: Shift + RMB / MMB now flies / pans like RMB / MMB (the camera ignores a Shift it has no use
  for); Shift + left drag in Select, Place and Zones stays "a drag with another key: no click, nothing else"
  (`press_step`, UI_DESIGN says so).
- `tools/qa/test_scene_tools.py`, two checks added where the data already stands: phase D (the viewport's own brush
  via `viewport.view brush_*`: a left drag in Foliage mode paints, the same drag with `mods="shift"` erases it and
  moves no camera) and phase W (Shift + click moves the selected mark: the picture shows it at the pointer and no
  longer where it was, one mark only; a click without Shift lays a second one). Docstring updated.

## B. One pick list, no dead kit functions (finding 9)

- Kit: `gz_ui::form::section` and `raised_section` (no caller) and their `key_of` are out. `form.rs` now holds
  `check`, `hint_field` and the new `secret_field` (the one password / token field: `gz-ui-mod`'s
  `local_password_field` and `gz-ui-release`'s `local_secret_field` were the same widget).
- Kit `pick.rs`: `PickList::empty(text)` (a wrapped sentence when no row is left) and `PickList::query(ctx, salt)`
  (what is typed, for a caller that offers a row for it). The "Add Module..." list and the Function picker of Mod
  Settings are the kit's `PickList` through `pick_popup`; the id typed that the game does not list is one more
  `PickItem` ("Add <id>"). `gz-ui-mod`'s `local_pick_list`, `PickList`, `PickRow`, the `search` and `pick_focus`
  fields are gone.
- One-line wrappers inlined: `gz-ui-mod` `local_check` (-> `form::check`), `gz-ui-pda` `local_check` (-> `Switch`) and
  `local_section` (-> `Section`), `gz-ui-level` `local_danger` (7 callers -> `Button ... GhostDanger`). Dead:
  `gz-ui-app` `local_text_field_id`, `gz-ui-content` `faded`. Secret fields -> kit `secret_field`
  (`gz-ui-mod/package.rs`, `gz-ui-release/submit.rs`, `local_secret_row`).
- The headers of every `local.rs` now say what is true ("What <surface> draws that no other surface does") and the
  crate docs (`gz-ui-mod`, `gz-ui-pda`, `gz-ui-release` `lib.rs`) list what is left.
