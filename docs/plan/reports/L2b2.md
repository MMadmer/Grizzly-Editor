# Report L2b2 - Details and the chooser; Build, Play, the menus and the level's actions

## 1. Built

**The level's actions (`crates/gz-ui-level/src/actions.rs`, new)** - every menu row, toolbar button and key of the
Level tab is an action over a command, keys live on Level (`Scope::Tab`):
- File: New Scene (Ctrl+N, `scene.new`), Open Scene... (Ctrl+O, `level.show dialog=open_scene`), Open Last Scene
  (`scene.open path=<the newest recent>`), Save As... (Ctrl+Shift+S); the shell's `file.save` is Save. A scene
  command refused for unsaved work (`code: unsaved`) is asked about in the action's reply with the kit's
  Save / Don't Save / Cancel and sent again with `save` / `discard` - the command never asks.
- Selection: Select All (Ctrl+A), Deselect All, Invert Selection (Ctrl+I) over `scene.select`; Hide Unselected
  (Shift+H) over `scene.set hidden=`; Ungroup (Ctrl+Shift+G), Place Group..., Save Selection as Group..., Mark as Mod
  Content / Base Level, Summary Info, Create Recovery Snapshot, Maximize Viewport (F11, `level.show maximize=toggle`).
  Hide Selected (H), Show All Hidden (Ctrl+H) and Group (Ctrl+G) are the viewport's actions (stream L2a); the Scene
  menu lists them by their ids.
- Build: Build Level (F5, `level.build`), Rebuild All (`force=true`), one action per step (`level.build_game`,
  ... `level.build_detail_light`: `only=<step> force=true`, titled Build Game Files, Build AI Map, ...), Build at
  Draft / Final Quality, Validate Scene (`level.validate`, findings in the kit's result dialog), Show Problems, Clear
  Problems (`level.problems clear=true`), Export Scene / Selection as OBJ..., Compile a Level Folder...; Play (F9,
  `level.play`), Play Clean, Play Without Building (`build=false`), Stop (`action=stop`, on only while a build, the
  compiler or the game runs), Reload Game Configs, Open Game Folder (`ui.reveal path=<game root>`: the folder test
  runs on the IO pool, audit D7).
- `gate(scene, Needs)` is the one rule an action of the scene is on by (a scene, objects, a selection) - unit tested.

## 2. Decisions

- **`level.show`, not `level.view`**: stream L2b1 owns `level.view` (the left panel and the Outliner, `view_cmd.rs`);
  the Level tab's own windows, popovers and the maximized viewport are `level.show`, so neither of us edits the
  other's parameters. Both are `view` commands.
- **File dialogs stay a person's**: `level.show dialog=open_scene` from MCP is refused with the command to run
  (`scene.open path=`); Summary Info opens for anyone (it is a window to look at).
- **No duplicate actions with the viewport**: Hide Selected, Show All Hidden and Group are L2a's; my menus list them.
  A unit test fails when a level action and a viewport action default to one chord.
- **Problems is a panel** beside the Output Log rather than a tab inside the log host (the log is `gz-ui-app`'s): the
  dock already does tabs per slot, and in Compact it sits beside Details because the log is a drawer there.
- **Delete in the painting modes asks nothing** (D8: one undo step), unlike the old confirm of the node removal.
- **"Advanced" rows** are a fixed list of keys in `details.rs` (`advanced`): `gz-scene`'s rows carry no such flag.
- **Reset arrows** only where the scene's field table has a default the row's value can be compared with (numbers,
  angles, vectors, colours 0..1, switches, words, empty picks); a spawn's entity properties have no default there and
  show none.
- **The Vec3 under its label** is drawn by Details itself (a label row, then a grid block) - the kit has no "value
  under the label" flag (Requests).
- **Selection actions select objects in every mode** (a mode never filters what Select selects); the painting modes'
  own Select All of nodes / decals are their panels' buttons.
- **The chooser is not the kit's `PickList`**: it needs the highlighted item for its preview, pictures in rows and
  most of the window's height; it uses the kit's ranking (`gz_ui::rank`) so the order is the same.
- The Build menu's step rows draw the state in the keys column (a status icon, the word right-aligned) and run the
  step's action; they are drawn from the status, not registered rows, because their state changes.
