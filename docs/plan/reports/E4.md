# E4 - the libraries' two last commands are jobs; the library's writers pass the guard; one more pick list

Closes the critic's findings 1 (blocker), 3 (the writers' half), 4, and the minors named in the brief. All code is in
`crates/gz-ui-previews`; the suites are `test_previews` K, `test_cli` I and `test_tour` A.

## What was built

### A. `library.sync` and `library.rewrite_descriptions` are commands (`libtools.rs`)

- Each starts its job itself (`sync_textures`, `sync_sounds`, `texture_library`, group `libraries`), waits for it with
  the library's `job_answer` and answers what it did; `wait=false` answers `{job}`. No window, no tab, no `started`.
  From `Grizzly-Cmd.exe run library.sync kind=texture_library -root <lib>` too.
- Own parameter structs, typed enums, words of the other library commands (`kind=texture_library|sound_library`).
  `library.reload` got its own struct too (`textures|objects|light_animations`), so its card no longer lists `sounds`;
  the unreachable branch is gone.
- Answers: sync = `kind`, `updated` (count), `names` (first 10), `up_to_date`, `failed` (first 10), `failed_count`; sounds
  add `orphan_count`, `orphans` (first 10), `retired`. Rewrite = `rewritten`, `names`, `unchanged`, `failed`,
  `failed_count`. A non-empty `failed` is the command's error `failed` with the same fields (the library's `job_answer`).
- **Which command asks in the window, and why.**
  - `library.sync kind=texture_library`: no question. It only makes what is missing or older, from sources, and keeps the
    description's parameters; it loses nothing.
  - `library.sync kind=sound_library`: the synchronisation itself needs no question; the one thing a person would miss is
    the orphans renamed to `.~ogg` / `.~thm`. That is a parameter of the command (`retire_orphans`, default false: the
    answer names them either way). The window action `library.sync_sounds` sends the command, and when the answer names
    orphans asks through the kit's confirm and sends the command again with `retire_orphans=true`.
  - `library.rewrite_descriptions`: rewrites the author's files in place (also upgrading an older format), so it is asked
    first. The action `library.rewrite_descriptions` sends the command with `dry_run=true` (writes nothing, answers the
    count and the first names), asks over that, and Yes sends the command again. `dry_run` is a parameter of the command.
  - Under `-nodlg` the action's logged answer is No: nothing runs (rewrite) / orphans stay (sounds). The commands never
    ask and never depend on it.
- The rewrite no longer writes a description that would come out identical, and keeps the age of one it writes (a
  rewrite used to make every description "of another age", so the next synchronisation rebuilt every game texture).
- Messages the author reads are sentences now (`libtools.rs`, `texsync.rs`, `sounds.rs`): "The smaller cube map was made.",
  "The texture '...' could not be read: ...", "The game texture '...' could not be made: ...", the normal map and gloss
  mask lines, "The game sound '...' could not be made: ...".
- The actions moved into `libtools::install` (ids unchanged: `library.sync_textures`, `library.sync_sounds`,
  `library.rewrite_descriptions`); the toolbar/More titles lose the "..." where no dialog precedes the work
  ("Synchronize Textures", "Synchronize Sounds"; "Rewrite Texture Descriptions..." keeps it). The two sync actions and the
  rewrite are disabled while the folder cannot be written.

### B. The writers pass the guard (`writer.rs`)

- `LibraryWriter` = `EditorDirs` + `gz_project::library_guard(&editor)` (derefs to `EditorDirs` for reads). Every write is
  one of its methods, each checking the path first: `write` (atomic), `create_dir_all`, `copy`, `rename` (both ends),
  `remove_file`, `set_age`. A refused write is an error in the guard's sentence; nothing is written before the check.
- Every writer of the crate takes it: `texsync` (`sync_texture`, `import_picture`, `synchronize_all`), `sounds`
  (`make_game_sound`, `save_sound`, `synchronize_sounds`, orphan renames), `lanim` (`write_lanims`, new, used by
  `save_lanims`), `libtools` (rewrite, smaller cube map), `textures` (import staging, save, rebuild). `EditorDirs` stays the
  read side, so a write cannot be made without a guard by type.
- Unit tests (`writer.rs`, `tempfile`, no program-named file): a fake game folder as the library - a save of each of the
  three libraries is refused and the folder is byte for byte (and age for age) what it was; a library of its own is written;
  a staged picture leaves no copy and the author's is renamed.

### C. The texture pick is the kit's (`library/texpick.rs`)

`Combo` field + `PickList` in `pick_popup` (None first, every texture, virtual rows), rows made once per read of the
library's list (keyed by the list's `Arc`) and only while the popup is open - the `list_picker` model. `local_texture_pick`
is gone; no `egui::ComboBox` is left in the crate.

### D. Minors

- The import folder keeps no copy: a picture the command staged is removed once it is in the library (also when the import
  failed or was stopped); one the author put there is renamed to `.~<ext>` as before.
- `test_tour` picks the first entry of Light Animations, Texture Library and Sound Library after opening each tab.
- Comments citing another program are gone (`libtools`, `texsync`, `local`, `sounds` x2, `lib.rs` doc, plus `paths.rs`
  `EFS.AppendFolderToName` / `FS.set_file_age` and `library/mod.rs` `FS.can_write_to_alias`).

## The cards as `help` prints them

```
library.sync (write) - Brings the texture or the sound library up to date with its sources: what is missing or older is made, as a job.
  kind: texture_library|sound_library (required) - The library to synchronize.
  retire_orphans: bool - sound_library: also rename the game sounds and descriptions that have no `.wav` any more to `.~ogg` and `.~thm` (never deleted). The answer names them either way.
  wait: bool - Answer when the job has ended; false answers the job at once.
Example: library.sync kind=texture_library

library.rewrite_descriptions (write) - Writes every texture description of the library in this editor's format, as a job.
  dry_run: bool - Write nothing: answer how many descriptions there are and name the first ones.
  wait: bool - Answer when the job has ended; false answers the job at once.
Example: library.rewrite_descriptions dry_run=true

library.reload (write) - Reads the textures, the scene's objects or the light animations again.
  kind: textures|objects|light_animations (required) - What to read again.
  discard: bool - light_animations: drop the unsaved changes of the library.
Loses data with: discard.
```
