# E7 - the manifest's check reads the values

Closes finding 2 of `CRITIC.md` and two of its minors (the "all modes" comments, `check` walking the editor's own
folders). Nothing is committed. Files outside the brief's list were not touched; what I would change there is in
"For the architect" below.

## What was built

1. **One table, one `accepts`.** `crates/gz-mod/src/reference.rs`: every `KeyDoc` of the reference page now carries a
   `Check` (`Free`, `Id`, `Version`, `Website`, `Tags`, `Target`, `Mode`, `OwnModeId`, `Repo`, `Description`, `Flag`,
   `Choice(words)`, `Words(words)`, `Number`, `Count`, `Rect`). The page's "what it takes" text and the rule that
   judges the value are the same row. `crates/gz-mod/src/rules.rs`: `accepts(check, value)` is the one judge (it calls
   `validate_version`, `validate_website`, `validate_github_repo`, `validate_mode_id`, ... - those functions stay the
   game's rules, nothing was retyped); `refusal(section, key, value)` is what `mod.set` and the form turn a value away
   with; `validate(doc)` is what the check, `mod.info` and every build say about the file.
2. **`validate` now takes the document** (`&ManifestDoc`, was `&Manifest`) and puts every problem at its line:
   `file`, `line`, `column` of the key (an indented key: its own column), `end_column` after the key. A key the file
   leaves out (`mod.target`) is at its section's header, else line 1. Callers moved: `gz-asset`'s `check_manifest`,
   `gz-build`'s `check_module` (so `mod.build` and `mod.package`, whose export goes through it), `gz-mod`'s
   `manifest_problems` (so `mod.info` and `mod.set`'s answer).
3. **Errors** (the editor refuses to save them): `mod.version`, `mod.website`, `mod.tags`, `mod.target_value` (also
   when a mode is written: `target = sideways` with `mode = night` was clean before), `mod.mode` (the `[module] mode`
   id, `*` allowed), `mod.mode_id` (`[provides_mode] id`: charset, 64 at most, no `*`; the old code, now at its
   line), `mod.github`, `mod.description` (4095 bytes), `mod.var_name`, `mod.var_twice`. Existing: `mod.id`,
   `mod.target` (no target chosen; now silent when the target written is the wrong-valued one, that has its own).
4. **Warnings** (the readers ignore them; the build goes on and reports them): `mod.key` (a key of `[world]`,
   `[start_kit]` never - it takes any item -, `[screens]`, `[screen.<id>]`, `[track.<id>]` that no reader takes, or one
   spelled in another case where the reader compares exactly), `mod.value` (a value none of them reads as written:
   flags, `mix | only`, `loop | next`, surfaces, `hide`, `fit`, numbers, counts, `rect`, `player_choice`),
   `mod.tags_case` (`Story`: the Mod Browser compares exactly). Keys of a section the editor keeps (`[budget]`,
   `[redirects]`, `[vfs]`, an unknown section, an unknown key of `[module]` / `[provides_mode]`) are never reported.
5. **Fixes where mechanical** (`fix` = the line to write): `github = owner/repo` from a pasted address, a flag / choice
   / target in the wrong case, the tag list in lower case, a key spelled in the wrong case.
6. **No rule in two places.** `mod.set` (`cmd.rs`): id, version, description, website, mode, target, `provides_mode`
   id, `[update] github` all go through `refusal`; the global's name and "declared twice" through
   `global_name_refusal` / `global_twice`; `flag_of` through `parse_flag`. The form (`gz-ui-mod/src/form.rs`):
   `validate_mode_ref` / `validate_own_mode_id` (the module's own mode id was checked for the charset only, now also
   for 64 characters, as the check and the packaging do), the description room from `gz_mod::DESCRIPTION_ROOM`. The
   tag vocabulary is `gz_mod::TAG_VOCABULARY` (see "What I did not prove" for `gz-release`'s copy).
7. **The build follows.** `mod.build` / `mod.package` refuse on the errors - now with every error, one per line (it
   was the first alone) - and report the warnings; `mod.info` lists them (`problems`). Checked by `test_cli` J.
8. **The minors.** The two comments (`model.rs`, `rules.rs`) say what the code does: empty `mode` = the ordinary game
   only, `*` lifts the limit. `gz-asset`'s `check`: `targets` drops files under the project's editor-only entries
   (`gz_project::is_editor_only_entry`: `temp\`, `releases\`, `logs\`, ... at the project root) both from the tree and
   from `walk_disk`; tooling was skipped already; `rawdata\` and the guides (build leaves-out, the author's own) are
   still checked; a check asked for such a folder (`check temp/...`) reads it. No layering problem: `gz-asset`
   already depends on `gz-project`.
9. **The reference page** (`asset.reference kind=manifest`): "any other word is refused" for tags and "Any other host
   is refused by the editor" for the website now say where (mod.set, the check, the build); a bullet under "Writing
   it" says what the check reports as an error and what as a warning, and what it never reports.

## What I did NOT prove

- The window: the Mod Settings tab's own Problems list is the form's (`form::check`), which I did not change except
  for the two mode-id rules; I did not look at it, and the Problems list of a tab that shows `mod.ltx`'s check (if one
  does) was not looked at. Only the commandlet's and MCP's answers were.
- What each value means in the game was not run: the flag words and the lists come from the readers' code
  (`gz-world`, `gz-screens`), held by tests of those readers, not from the game's engine.
- `disable_game_updates = yes` / `on`: the model reads only `true` / `1` as on (as before), the check accepts the
  eight flag words, so those two are silently off. I do not know what the game's reader does with them.
- A key spelled in another case in `[module]` etc. (`Version = ...`) is read by nobody and not reported (the
  brief asks the warnings for the area sections only); `[world]`'s five rules are accepted in any case, as their
  reader does, the other area keys only exactly.
- `target = existing` without a `mode`, or `new` without `[provides_mode]`: the form calls it "required", the check
  says `mod.target` (as before) and nothing sharper; not changed.
- `mod.package` was proved to refuse through the same check with one wrong tag; the other errors reach it by the
  same path (`check_module`), not each one. `release_gate` runs before it and says its own sentence for version,
  website and repository.
- The corpus is six manifests (the author's three projects and the game's `mods`); `GRIZZLY_TEST_FULL` reads
  all of them already. A classic module outside those could meet a rule I could not see.
- `test_assets` was not extended: the scratch folder case is in `test_cli` J (the brief allowed either).
