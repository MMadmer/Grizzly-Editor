## 2. Decisions

- Own syntax tree and evaluator for the document, the LuaJIT-model judge kept as the arbiter: parity is proven on
  unit cases, 400 generated files, the repo corpus and 25 assets of the game repo (21 read, 4 refused, the same).
- A list whose items do not line up with the model (an item the model skipped) is written whole: a positional diff
  over a mismatch would move values to the wrong items.
- A missing header is E001 (the game refuses the file) and the first save adds it as the first key; a save never
  writes version 0.
- Positions the auto-layout chose are not saved until the author moves the node (`AutoPos`).
- The pickers' character list stays stale-while-revalidate (it never makes a caller wait); the suites that read it
  right after a write wait for it (`test_build_contents` C, `test_asset_icons` A).
- The PDA document is one text: its merge puts the pane's changed values into the file's new text (the pane's
  comment edits in that text are the file's), and Take Theirs takes the whole file; `asset.take_theirs index` is
  optional (all conflicts) for every kind.
- The Characters tab now saves from the character it READ, not from the roster at save time: before, a form saved
  after an outside change wrote its stale values back over that change.
- `ReadFailure` boxes its problem (clippy `result_large_err`); `Step::Save` boxes its plan.
