## The reference's outline

`mod.ltx - the module manifest` / **Writing it** (case, comments, quoting, lists, how to edit and check) /
**First, the target: a module is for ONE game** (the four ways, the `mod.set` command) / sections, each with its
keys: `[module]` (id, name, version, author, description, website, thumbnail, tags, api, target, mode,
disable_game_updates), `[provides_mode]` (id, title), `[requires]`, `[order]` (after, before), `[conflicts]`,
`[update]` (github), `[exclude]`, `[vfs]`, `[vars]`, `[pda]` (layout), `[commands]`, `[command.<name>]` (help, args,
cheat), `[world]` (the five rules, player_choice, levels, area, locked_levels, locked), `[start_kit]` (money, perks,
items), `[screens]` (six policy keys), `[screen.<id>]` (show, levels, modes, weight, music, hide, layer, fit,
opacity, rect, texture, sound), `[track.<id>]` (file, play, weight, volume) / **Example** (a complete module with a
mode of its own) / **Modes of the linked game** (or why there are none) / **Left as written** (`[budget]`,
`[redirects]`: the game's, kept by the editor).

`[requires]` and `[conflicts]` are described from the game's loader (`xms_core.cpp`): the id is the key, the value
is not read; a missing required module or an installed conflicting one switches the module off.

## The sentences as they read now

The problem (`mod.target`, error, fix `target = default`):

> no target game mode: write `target = default` under [module] in mod.ltx for the ordinary game, `mode = <id>` with
> `target = existing` for a mode of the linked game, or a [provides_mode] section with `id = <id>` and `target =
> new` for a mode this module adds. The command: mod.set set={"module":{"target":"default"}}; `reference manifest`
> lists the modes and every key. In the window: Mod > Mod Settings, Game Mode

`mod.set`: `set` - "What to change, by section of mod.ltx: {"<section>": {"<key>": value}}. An empty text removes a
key. `module`: id (a-z 0-9 _ . -), name, version (1 to 4 numbers, 1.2.0), author, description, website (https,
ap-pro.ru or moddb.com), tags (a list from the Mod Browser's words), disable_game_updates (true | false), and the
target: `target` is `default` (the ordinary game), `existing` (a mode of the linked game, with `mode`: its id),
`new` (a mode the module adds, with `provides_mode`) or `any` (every game, with `mode` = `*`). Setting a mode id or
`provides_mode` also sets `target` unless it is given; `mode` = `*` needs `target` = `any`. `update`: github
(owner/repo). `order`: ... `provides_mode`: {id, title} ... Every key and value: asset.reference kind=manifest."
Example: `set={"module":{"target":"default","version":"1.2.0"},"update":{"github":"owner/repo"}}`.
