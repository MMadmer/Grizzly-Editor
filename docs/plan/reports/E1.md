# E1 - the library tabs get their commands; a surface says when it is not ready

Closes the critic's findings 3, 7, 8 and the first minor of 10. Nothing is committed.

## What was built

### A. The three library tabs by command (finding 8)

- **`library.set`** (write). `kind`, `item` (exact name, any case; left out = the tab's selection), `set` (named
  keys), `save` (default true). Texture keys mirror every row of the Details panel (`type`, `format`, `mips`,
  `mip_filter`, `bump_*`, `detail_*`, `material*`, `dither*`, `fade_*`, `border_*`); sound keys `quality`, `min_dist`,
  `max_dist`, `max_ai_dist`, `base_volume`, `game_type` (`max_dist: "from_min"` and `min_dist: "from_max"` are the two
  Attenuation buttons); light animation keys `fps`, `frames`, `keys` (`{"<frame>": "#RRGGBB" | null}`), `move_key`
  (`{from, to, follow}`). Words are the editor's own (`DXT5`, `Cube Map`, `Weapon shooting`), any case. All or none; an
  unknown key is refused with the nearest real one; a key a type has no row for is refused (same rules as the rows).
  It answers `changed` (key, from, to), `saved`, `dirty`.
- **The edits are one set**: the three libraries' pending edits moved out of the tabs into an `Editor` service
  (`library/stores.rs`, `LibraryStores`: the three stores and the saving flags). A tab shows them, the Details rows
  post to them, `library.set` posts to them: one set of pending changes, one Save (`start_texture_save`,
  `start_sound_save`, `save_lanims`, which the tab's Save and the command both run). It works with no tab open; the
  tab, when open, follows. `save=false` leaves an unsaved, undoable edit for `doc.save`.
- **`library.play`** (view): `kind` sound_library or light_animations, `action` play | stop, `item`. Without a window
  `no_window`.
- **`library.import`** (write): `from` (files anywhere; none = what the import folder holds), `set` (description keys
  for every picture), `overwrite`, `wait`. Copies into the import folder, imports, as one job (stage per picture, Stop,
  group `libraries`). It refuses with code `exists` when it would replace a staged picture or a texture of the library
  and names them; `overwrite` is in `destroys_with`. The window's Import over New Textures now asks the same through a
  confirm that names what is replaced (up to ten) before it starts.
- **`library.rebuild`** (write): decision - the Sound Library's Rebuild is not an import (nothing comes from outside),
  so one concept, one name each: `library.import` brings pictures in, `library.rebuild` makes the game texture / game
  sound of an entry again from its source (`kind=texture_library|sound_library`, `item`, `wait`; `small=true` is the
  cube map's Smaller Copy, which had no command either).
- **`library.view`** gained: `action=check` (Check New Textures: looks in the import folder, turns the tab into New
  Textures, opens the tab if it is closed - so `library.check_textures` now does what it says), `alpha`, `auto_play`,
  `types` (the texture type filter), `key=previous|next`, and `simulate_drop` / `x` / `y` (lands files at a window
  point the way a drop does, like `screens.view`; waits for the import it started). `kind` is now a typed enum.
- **`library.reload`** gained `kind=light_animations` and `discard` (`destroys_with`); with unsaved keys it answers
  `unsaved`. The window's Reload asks through the action's `reply` and runs the command again with `discard`.
- **Every toolbar button is an action**: Save / Import = `file.save`; Check New Textures, Synchronize ..., Rewrite ...,
  Reload Textures, the five type filters (`library.type_*`, checkable), Play / Stop / Auto Play / Rebuild of the sounds,
  Reload / Alpha / Previous Key / Next Key / Add Key / Delete Key / Move Key Earlier / Later / Play / Stop of the light
  animations. Each tab publishes what it is (`LibraryFacts`, an `Editor` service) so an action says whether it is on and
  why not and works out its arguments (the frame, the colour). The tabs draw them with `toolbar_button` / `menu_row`.
  The Sound Library's row ends with More.
- **The Texture Library takes a drop**: pictures from Explorer and picture tiles of the Content Browser, through the
  kit's `gz_ui::drop::Zone` over the whole tab (catch-all), run `library.import`. The empty state says what the tab
  reads and "Drop pictures here to add them."; the button of the empty state and the banner say "Check New Textures" /
  "Check" (they only look).
- `libtools::smaller_cube_map` now returns its job, so `library.rebuild small=true` can wait for it.

## Decisions

- Edits live in a service, not in the tab, so a command and a person edit the same thing and a command needs no window.
- `library.set` writes by default (`save=true`): an agent that sets and leaves must not lose the change; `save=false` is the
  person's unsaved edit. A save through `library.set` writes only that entry's edit (`only`), not other pending edits.
- `library.import` has no `kind`: it brings pictures; sounds have no outside-in step in this editor.
- The kit zone `gz_ui::drop::Zone` is used, not `gz-ui-pda`'s `local_file_drop_zone` (the kit has had its own since the
  start page; the pda one is a second copy of the same thing).
- Import replacing library textures asks in the window (the editor's rule for destructive operations); a command refuses
  `exists` unless `overwrite`.

  `library.view simulate_drop`); the kit zone itself is the one the Start page and the viewport use.
- The confirm dialog of New Textures' Import (`import_replaces`): written, built, not driven (the QA editors run `-nodlg`,
  which answers No).
- The window's Reload asking for unsaved keys (`reload_reply`): the command's `unsaved` is proven, the dialog is not.
- Pictures of the new toolbars at both tour sizes were only looked at at one size (light animations; sound / texture rows
  pass the tour's audit at both).
- `library.set` / `library.import` in a commandlet (no window): written to need none and the services are the editor's,
  but only run through the window's editor.
- `Footer::busy` / `card_busy` reporting `loading`: compiled and used by the tour's `settled`, but in QA no dialog stays
  busy, so no busy dialog was seen failing the wait.
