# Q1 - the suites and the checks

## 1. Built

**One client: `tools/qa/qa.py`** (814 lines). It holds the target (`exe()`, `PORT`, `home()` - made lazily, so importing it has no side effect), the socket client (`cmd`, `call`, `batch`, `gate`; `escaped=False` sends raw UTF-8), the editor's lifecycle (`Editor`), the project copy and its guard (`copy_project`, `guard_project`), `check(..., timing=True)`, `run_phases` (letters, `needs`, setup phases run quietly), `stalls`, `shot`, `until`, the mock (`mock_exe`, `Mock`) and `suite()`, the main every suite ends in: `--project --only --shots --keep`, the copy, `TITLE: DONE n/m`, the wall-time split.

- `Editor`: starts on its own port and home (hidden or shown, headless, `-qa_github` with every service on the loopback nowhere), closes over the socket and never kills. **Ready means the editor answers AND `state` names the project it was started on as open** (the architect's finding), then one frame is drawn and the tasks run out. `close()` first asks `perf.stalls`: a stall the suite did not declare (`stalls_allowed(why)`) fails it, as a `SLOW` line. `launch()` is a start with no wait (a second start that hands over and ends); an editor that restarted itself (the updater) is closed through the port and waited for by its command line.
- A work folder that is not absolute under the system temp folder stops the suite (exit 2) before it runs: the stray `Grizzly Editor\` in the repository root (the update suite, a relative `work`) cannot happen again. `suite()` always makes the work folder, with or without a project.
- `check(..., timing=True)` prints a failure as `SLOW`; `run_all.py` reads that (`only_timings`: a suite whose failed checks are all `SLOW` is measured again alone, and that run is its result). `log_trouble` (device error, panic) is kept; `GRIZZLY_QA_KEEP_LOGS` and the architect's `<suite>-<time>-<log>` naming are kept.

## 2. Decisions

- **`Args` stays** as the name of the request map (`pub type Args = Map<String, Value>`): about 60 files of other crates build a call with it (`Editor::call` is by name and takes JSON), so it cannot go with the registry's untyped registration; `ArgsExt` (the forgiving readers) is deleted. Its three users (`gz-ui-previews` `library/{lanim,sounds,textures}.rs`) read the already typed `library.view` request with plain `get`.
- "No command without a card" is held three ways: the type (no registration without one), the `help` line (`check.sh`), and the source grep (`check.sh`); the registry test `every_card_is_worth_reading` in `grizzly` is the quality bar of a card.
- A text cut with an ellipsis is not a failure of the tour (paths, status lines: the design, the tooltip holds the whole); an escape, or text cut to nothing in a box that has width, is.
- One suite per area, each under two minutes: none was over, so the merges were by overlap only (stress into the bridge suite, the lifecycles into one). `test_assets`, `test_asset_icons`, `test_behaviours` and `test_graph_ui` stay apart: they prove different things (files, tiles, vocabulary, the canvas) and each takes 10-20 s.
- `test_cli` phase H and `test_ui_shell` phase A are the only ones that need a console or a visible window; both are kept as they were.
- A stray `Grizzly-Cmd.exe frobnicate` of mine (an unknown word is a path to open, so it starts a windowed editor) opened an editor in a scratch home; I ended it with TaskStop (no project was open). No suite does that.
- I ran `git rm --cached` on one file once by mistake and undid it at once with `git reset -q -- tools/qa/qa_target.py` on that path; the index is as it was.
